# Спецдоставка

Законченная первая игровая доставка по `Spetsdostavka_TZ_v2.md`: шесть комнат Главпочтамта, посылка с правилом «ПЕРЕРЫВ», пространственное передаточное окно и концерт в Малом зале.

## Запуск

Нужен Node.js 22.12+ и npm. Проверено на Node.js 26.8.1.

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Это компьютерная игра с клавиатурой. Сервер привязан к локальному интерфейсу.

```sh
npm run build
npm run preview
```

`dist/` — готовая статическая сборка. Размещать через обычный HTTP-сервер; для подпапки задайте `--base`, как в примере GitHub Pages ниже. Backend, API-ключи и аккаунты не нужны. Открытие `index.html` через `file://` не поддерживается.

## GitHub Pages

Игра: https://region23.github.io/spetsdostavka_game/

Workflow `.github/workflows/pages.yml` запускается при пуше в `main` или вручную через Actions. Он устанавливает зависимости, проверяет тесты и маршрут, собирает игру и публикует `dist/`. В Settings → Pages источником должен быть выбран **GitHub Actions**.

Сборка для этого адреса и локальная проверка:

```sh
npm run build -- --base /spetsdostavka_game/
npm run preview -- --base /spetsdostavka_game/ --port 4174 --strictPort
```

В другом терминале:

```sh
GAME_URL=http://127.0.0.1:4174/spetsdostavka_game/ node tests/browser-production.mjs
```

При переименовании репозитория обновите `--base` в workflow. Динамические пути к изображениям используют `assetURL()` из `src/assets.ts`. Backend и секреты для работы игры не требуются; прогресс хранится в браузере. Локальное сохранение не переносится автоматически на опубликованный сайт.

## Управление

| Клавиша | Действие |
| --- | --- |
| A / D, ← / → | Разгон, бег и точная остановка |
| Space | Прыжок, подъём из висения |
| S / ↓ | Спуск с подъёмника; контролируемое висение у края; отпустить край |
| E | Одно контекстное действие: взять, оставить, передать, вернуть или вручить |
| F | Открыть / закрыть пломбу у переносимой или ближайшей посылки |
| Esc | Пауза |
| R | Повтор комнаты с подтверждением |
| F2 | Коллизии, координаты, фазы и безопасная точка |

Основные клавиши переназначаются в настройках. Помощь и добровольный пропуск препятствия доступны через паузу. Нет жизней, повреждения груза или предельного времени.

## Что работает

- Шесть комнат с отдельными контрольными точками и единой доставкой.
- Поле радиусом 220 логических пикселей, сохраняющее фазу четырёх типов механизмов. Поле проходит через стены, принадлежит посылке и действует после её размещения.
- Переноска на движущихся платформах, буфер прыжка, coyote time, захват края, подтягивание и спуск.
- Передаточное окно в обе стороны: ошибочно переданную закрытую посылку можно вернуть. Служебный турникет явно требует передать отправление через окно.
- Загрузка с обработкой ошибок, пропускаемая заставка, меню, иллюстрированное вступление, задание, настройки, пауза, помощь, титры, финальная сцена и квитанция.
- Три страницы знакомства с Проспектом без таймера, повторное чтение через «О городе». По маршруту открываются записи о городе; реплики идут по очереди в нижней панели и сохраняются для перечитывания на паузе.
- Сохранение начала комнаты и завершённой доставки. Пауза при потере фокуса и скрытии вкладки; возврат требует явного продолжения.
- Регулировка музыки, эффектов, речи, субтитров, подсказок и движения; доступный браузеру полноэкранный режим.
- Три сгенерированных интерьера, сгенерированные курьер и сумка; отдельные прозрачные спрайты и атлас. Сумка привязана к отдельной точке.
- Синтезируемые музыка и эффекты. Необязательная системная речь использует голоса устройства; отсутствие аудио не мешает игре.

## Устройство

Phaser **4.0.0**, TypeScript **5.9.2**, Vite **6.4.3**. Версии зафиксированы в `package-lock.json`.

`rooms.ts` содержит геометрию и траектории. `simulation.ts` — детерминированный контроллер героя, посылки и механизмов с фиксированным шагом 60 Гц. `storage.ts` — проверяемые снимки и настройки, `lore.ts` — вступление и записи о городе, `narrative.ts` — очередь реплик и история разговоров, `audio.ts` — звук, `scene.ts` — отрисовка, `main.ts` — ввод и экраны.

Осознанное техническое отличие от стартовой основы ТЗ: прямоугольные коллизии и перенос на механизмах реализованы собственным кинематическим контроллером, а не Arcade Physics. Это позволяет тестировать точный порядок «поле → механизмы → перенос героя → коллизии» отдельно от браузера. Phaser отвечает за графику, загрузку и цикл отрисовки. Никакой физики, привязанной к частоте кадров, нет.

Творческие упрощения первой версии: восемь рисованных поз используются для всех состояний движения и взаимодействия; финал — короткая сценическая композиция; музыка синтезируется, речь не записана актёрами. Это игровая версия для внешнего теста, не заявление о завершённой пользовательской приёмке ТЗ.

## Проверки

```sh
npm test
npm run test:route
npm run test:browser
```

Браузерные проверки требуют запущенного `npm run dev` и Chrome. Задать свой исполняемый файл можно через `CHROMIUM_PATH`; в текущем окружении также используется установленный Chrome for Testing. Пример на macOS:

```sh
CHROMIUM_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:browser
```

Проверка маршрута использует реальные клавиатурные события и управляемые браузерные часы. Она не телепортирует героя и не пропускает головоломки. Набор знакомства с миром проверяет вступление, старые сохранения, записи и нижнюю панель на двух размерах экрана. Набор восстановления отдельно проверяет паузу, повтор, помощь, переназначение, удержание F, перезагрузку, отказ хранилища и аудио, повреждённые данные и отсутствие обязательного изображения.

Редакторский разбор экранов и лора: `docs/narrative-audit.md`. Результаты и границы проверки: `docs/verification.md`. Происхождение материалов: `public/assets/manifest.json`. Полные промпты: `docs/asset-prompts.md`. Снимки проверок: `output/`.
